# Working tickets and issues

Tickets come from /to-tickets as local files (`plans/<feature>/tickets/`) or GitHub issues, or are issues the user names (`build 12 14`, issue URLs, or `milestone "<name>"`: its open issues with the agent or human label, `gh issue list --milestone "<name>" --state open --limit 1000 --json number,title,labels`; a source issue holding tickets has neither label). Work them by `docs/agents/issue-tracker.md` (Claim, Release, Priority), or without it by the defaults in [no-tracker-doc.md](no-tracker-doc.md). Each ticket is a milestone; its acceptance criteria are its Done when.

- **Read** each ticket whole (the file, or `gh issue view <n> --comments`), plus the plan or parent issue it was split from.
- **Drafts and planned issues.** A draft-labelled issue is never built: leave it out and point to `/plan-this issues <n>`. A planned issue is a plan file: build it from its plan comment (the one holding `Created <date> with /plan-this`), with `Fixes #<n>` in the PR.
- **Order:** blockers first, then high, normal, low priority. A ticket starts once everything in its `Blocked by` is done. When the user named the issues, they are the set: an open blocker outside it holds its ticket back, and you report it.
- **Human tickets** (the human label, or `Who: human`) are the user's: work every agent ticket they don't block, and list each with what it needs.
- **Claim** each ticket before its first change, as the tracker doc says. You claim and finish even when a child builds. On a lost claim, leave that ticket and the ones it blocks, and report the winning claim.
- **Finish** when the check passes. On GitHub, open the PR with `Fixes #<n>` and wait for green CI ([fix-ladder.md](fix-ladder.md)). Merging publishes: land it (the doc's Land command, else a squash merge) only on a go-ahead the user gave, such as "merge if green", then triage the run on the merge commit and release the claim as the doc's Release (Done) says. Without the go-ahead, report the green PRs and keep the claims. Locally, set `Status: resolved`.
- **Resume.** A resolved local ticket or closed issue is done. A ticket with an open PR from an earlier run awaits its go-ahead: list it, don't rebuild it.
- **Progress record.** The ticket's status is its tick. Build log lines go in the plan file the tickets were split from; without one, under `## Build log` in the ticket's own file, or as a comment on the issue.
